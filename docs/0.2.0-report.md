# SpotifyConnect 0.2.0 integration report

This release migrates the physically validated Phase 7 implementation from
`C:\Projects\Squeezify` into the clean production project. The upstream
librespot revision is `a1b66d3c8a14e55a9572a9e17467150dca618c9a` (0.8.0).
The vendored tree contains only the source needed to reproduce the binary; its
build output and research evidence are excluded.

The migrated local changes are in `native/librespot/audio/src/fetch/streaming.rs`,
`audio/src/fetch/mod.rs`, `audio/Cargo.toml`, `playback/src/player.rs`,
`playback/src/decoder/passthrough_decoder.rs`, `playback/Cargo.toml`, the
workspace `Cargo.toml`, and `playback/src/audio_backend/phase5_fifo.rs`. They
are the `streaming-only` Cargo feature and reader:
64 KiB sequential CDN ranges, a four-entry bounded queue, AES-CTR decryption,
restricted seek, Spotify's custom Ogg prefix handling, and passthrough decoder
startup without the normalisation probe. The Phase 7 FIFO guard remains in the
playback backend. The ARM build uses target
`armv5te-unknown-linux-musleabi`, ARM926EJ-S, soft-float, static linking, and
the Linux 2.6 compatibility wrappers in `native/linux26-compat`.

The exact build is `build/build-native.sh`: librespot is compiled with
`rustls-tls-webpki-roots,with-libmdns,passthrough-decoder,streaming-only` and
the bridge/supervisor are linked with the same compatibility shim. The local
bridge binds only to `127.0.0.1:17880`, accepts `GET /spotify.ogg` over
HTTP/1.0, and forwards bounded Ogg pages from the protected FIFO.

Authentication uses librespot OAuth device authorization on first run. The
supervisor writes a machine-readable `status.json` containing `starting`,
`pairing`, `connected`, or `error`; it does not expose tokens. The applet shows
the pairing URL/code and polls without blocking the UI. QR display is deferred.

Credentials use librespot's supported `--system-cache` facility at
`/etc/squeezeplay/userpath/SpotifyConnect/credentials.json`. The directory is
created mode 0700 and the credential file is created by librespot mode 0600.
This user path is persistent across reboot and SqueezePlay restart and is
outside the installed applet directory, so an applet upgrade does not remove
it. `Disconnect account` removes only this file and the local volume file.

The default device name is `Squeezebox Radio`; it is stored in applet settings.
After successful pairing the applet stores `enabled=true` and starts the
engine automatically after boot when credentials exist. A fresh install does
not open a pairing UI by itself.

four native artifacts, Lua applet, and strings. Current build outputs are:

Physical first-pairing, persistent restart, reboot, pause/resume, track
transition, and 60-minute acceptance results are intentionally recorded as
pending until this 0.2.0 package is installed on the Radio. The framework and
Phase 7 source already provide the validated compressed audio path; this phase
adds the production authentication, persistence, lifecycle, and UI integration.

Known limitations remain: arbitrary seeking is unsupported and a nonzero seek
may restart a track, Spotify remote volume synchronisation is not implemented,
QR is deferred, and the CHBN URL remains available only through the existing
development test helper rather than the normal production menu.
